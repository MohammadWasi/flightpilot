# Provider feasibility and launch decision

Research checked **10 October 2026** against the primary sources linked below. Public documentation establishes API design, not approval of FlightPilot's business. **No provider credentials, commercial contracts, payment approval or live account were supplied. No authenticated supplier sandbox call or production transaction was verified during this research.**

## Decision

Use **Duffel's documented test API as the initial integration target**, subject to obtaining a `duffel_test_` token. Its first-party sandbox supports search, orders and order retrieval. The credential-free development mode must be separately named **local simulation** with synthetic fares and references; it is not an airline or Duffel sandbox booking. Duffel's sandbox uses a fictional airline and does not establish real schedules, prices or India inventory. [Duffel test mode](https://duffel.com/docs/api/overview/test-mode)

**No production provider is approved for this project yet.** Preserve the requested priority: use Duffel only after written business, content and settlement approval. If that cannot support the India business, obtain TBO onboarding and certification before implementing or enabling its purchasing adapter. TBO is a credible India-focused alternative based on its documented domestic/LCC workflows; choosing it for production today would still be premature. Do not assume that public documentation grants account access.

## Duffel implementation evidence and boundaries

- **Search and refresh:** create an Offer Request, retain provider passenger IDs, and retrieve the selected offer immediately before checkout. Offers can expire or change price. Official test routes exercise missing offers and price changes. [Search guide](https://duffel.com/docs/guides/getting-started-with-flights), [Test scenarios](https://duffel.com/docs/api/overview/test-your-integration)
- **Baggage:** preserve segment/passenger entitlements and the prices/IDs of purchasable services. Unknown baggage is unknown, not zero-cost included baggage. Only book services that the selected offer makes available. [Adding extra bags](https://duffel.com/docs/guides/adding-extra-bags)
- **Payment-aware pricing:** the current guide uses `POST /air/offers/{id}/actions/price` with intended payment methods and services. Card surcharges and charged currency can differ from search. Display the actual payable total and require renewed approval when it changes; booking must use matching services and payment method. Do not copy the older changelog's PATCH verb blindly. [Accurate pricing guide](https://duffel.com/docs/guides/getting-an-accurate-price-before-booking)
- **Card collection:** Duffel Cards uses a provider component so raw card details need not touch FlightPilot's server. Complete the issuer's 3DS flow, and proceed only with a ready-for-payment session. Supplier-card payments require Duffel approval; this is distinct from Duffel Payments and does not establish India eligibility. [Customer-card guide](https://duffel.com/docs/guides/paying-with-customer-cards), [Approval announcement](https://changelog.duffel.com/announcements/we-now-support-card-as-an-available-payment-method)
- **India limitation:** the available Payments country article is dated March 2023. India is absent. Obtain current written confirmation; neither availability to travellers worldwide nor a working test token proves eligibility of an India-registered merchant. The Links help index exists, but its detailed country answer could not be verified in this research. **Duffel Links remains unsupported/unverified for this launch.** [Payments country list](https://help.duffel.com/hc/en-gb/articles/4409049043730-In-which-countries-is-Duffel-Payments-available), [Links help index](https://help.duffel.com/hc/en-gb/sections/10092975519378-Duffel-Links)
- **Booking status and servicing:** retain the order ID, retrieve the order, and inspect provider-issued documents and current status. Respect `available_actions`; cancellation/change capability varies by order and airline. A cancellation quote is not a completed refund. [Orders reference](https://duffel.com/docs/api/orders/create-order), [Cancellation workflow](https://duffel.com/docs/guides/cancelling-an-order)

## TBO implementation notes for a later approved adapter

The documented sequence is Search → FareRule → FareQuote → optional SSR → Book/Ticket → GetBookingDetails. FareQuote refreshes the selected itinerary. Non-LCC Book and Ticket are distinct; LCC uses Ticket directly. SSR can price baggage/meals where supported. Preserve `TraceId`, `ResultIndex`, booking ID and PNR; recover uncertain results through status retrieval before deciding whether a retry is safe. Never automatically set `IsPriceChangeAccepted` after a price increase. [Search](https://apidoc.tektravels.com/flight/Search.aspx), [FareRule](https://apidoc.tektravels.com/flight/FareRule.aspx), [FareQuote](https://apidoc.tektravels.com/flight/FareQuote.aspx), [SSR](https://apidoc.tektravels.com/flight/SSR.aspx), [Book](https://apidoc.tektravels.com/flight/Book.aspx), [Ticket](https://apidoc.tektravels.com/flight/Ticket.aspx), [GetBookingDetails](https://apidoc.tektravels.com/flight/GetBookingDetails.aspx)

TBO's public samples contain HTTP service URLs. Do not send credentials or passenger details to those URLs. Obtain the supplier's currently approved HTTPS staging/production endpoints and security requirements during onboarding. The product has multiple public documentation surfaces, so confirm which contract/version applies. Certification includes supplier review, signoff and static public-IP whitelisting. [Certification](https://apidoc.tektravels.com/flight/Certification.aspx)

## Amadeus historical context

Historical Self-Service production documentation required a consolidator agreement for ticket issuance, approved-market eligibility and compliance with local rules. India was absent from that historical exclusion list, which is **not current Enterprise eligibility approval**. Historical support documentation routed ticket changes/refunds through the consolidator. The old Flight Offers Search tutorial excluded low-cost carriers and several major airlines, a material drawback for India fare comparison. These facts explain why a reservation API alone cannot fulfill the product's ticketing promise. [Historical production guide](https://amadeus4dev.github.io/developer-guides/API-Keys/moving-to-production/), [Historical FAQ](https://admin.developers.amadeus.com/self-service/apis-docs/guides/developer-guides/faq/), [Archived flight tutorial](https://github.com/amadeus4dev/developer-guides/blob/master/docs/resources/flights.md)

## Evidence required before enabling production

1. Written supplier approval of the actual India legal entity, sales model and AI/MCP presentation of data; signed distribution and payment agreements.
2. Account-specific Indian carrier and international route coverage, supported passenger categories, INR availability/settlement and known service/payment/FX fees.
3. Approved hosted payment collection, 3DS, refund and chargeback process; an explicit decision on merchant of record and customer support responsibilities.
4. Authenticated supplier sandbox acceptance: search, price change, expired offer, booking, issued-ticket retrieval, timeout reconciliation and cancellation/refund scenarios.
5. Supplier certification where required, production credentials held only on the backend, and a reviewed operational launch procedure. No automated production purchase test.

Until these conditions are met, the application must clearly report simulation or supplier-test provenance, reject production credentials/purchases, and never describe generated fixture references as real PNRs or e-tickets. INR is a preference; when the supplier returns another currency, preserve that currency and avoid an invented conversion.
